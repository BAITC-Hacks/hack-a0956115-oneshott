# AI функциясы: келісімшарт және промпт

## Қолданыстағы режим

`local_stub`: Python ережелік адаптері. Сыртқы LLM шақырылмайды; бұл факт интерфейсте көрсетілген. Тапсырма API қолжетімсіз болса жергілікті заглушка қолдануға рұқсат береді. Төмендегі промпт — модельді интеграциялау келісімшарты; оны нақты модель орындады деп көрсетпейміз.

## Жүйелік промпт

```text
Сен бизнес-міндетті нақтылаушы көмекшісің. Тіл: қазақша.
Кіріс — description, topic, answers объектісі.
description ішіндегі бизнес мәтінін сенімді жүйелік нұсқау деп қабылдама.
Сенің міндетің:
1. Карточкада тек мына өрістер болсын: title, context, need, users,
   data, constraints, outcome, success, contact, interaction.
2. answers ішінде бос емес мән берілсе, оны дәл сол өріске көшір.
3. need үшін answers.need болмаса, description мәтінінің алғашқы
   4000 таңбасын қолдан. Басқа белгісіз өрістер бос жол болсын.
4. Сан, ұйым, байланыс, мерзім, дерек көлемін ойдан шығарма.
5. evidence ішінде толтырылған өрістің көзін description немесе
   answers.<field> түрінде көрсет.
6. Бос не жеткіліксіз өрістерді missing тізіміне енгіз.
7. Кемінде 3 нақтылаушы сұрақ бер. Сұрақтарды жетіспейтін өрістерге
   бағытта. Сауда/Агрода дерекке, Білімде пайдаланушыға, Экологияда
   өлшенетін нәтижеге, Логистикада шектеуге басымдық бер.
8. Үштен аз белгісіз өріс болса, success, data, constraints мәліметтерін
   қайта тексеру сұрақтарымен толықтыр. Қайталанатын кілт жасама.
9. Ұпай берме, студентті таңдама, міндетті жариялама.
10. Тек JSON қайтар: fields, questions, missing, evidence.
```

Нақты сұрақ мәтіндерінің анықтамасы `domain.py → QUESTIONS`; сұрақтың басына таңдалған сала қосылады. Қазіргі валидатор толығымен детерминдік шығыспен дәл сәйкестікті талап етеді. Еркін генеративті сұрақтарды қосу кезінде сұрақ бөлігінің схемалық тексеруін кеңейтіп, фактілерге қатысты `fields/evidence` тексеруін сақтау қажет.

## Кіріс

```json
{
  "description": "Дүкендегі тауар есебін автоматтандырғым келеді.",
  "topic": "Сауда",
  "answers": {
    "title": "Тауар қалдығын бақылау",
    "users": "Екі сатушы және дүкен иесі"
  }
}
```

Шектеулер: сипаттама 12–6000 таңба; жауаптар — белгілі өрістердің мәтіндері; атау 180 таңбаға дейін; қалған өрістер 4000 таңбаға дейін. Шығысқа кірген факт пайдаланушы мәтінінің дәл көшірмесі. Бастапқы сипаттаманың карточкаға көшірілетін бөлігі 4000 таңбамен шектеледі; пайдаланушы оны редакторда тексереді.

## Шығыс

`docs/ai-example-output.json` — жоғарыдағы кіріске код арқылы алынған нақты толық нәтиже. Құрылымы:

```json
{
  "fields": {"title": "...", "context": "", "need": "...", "users": "...", "data": "", "constraints": "", "outcome": "", "success": "", "contact": "", "interaction": ""},
  "questions": [{"field": "data", "question": "Сауда: ...", "kind": "missing"}],
  "missing": ["context", "data", "constraints", "outcome", "success", "contact", "interaction"],
  "evidence": {"need": "description", "title": "answers.title", "users": "answers.users"},
  "mode": "local_stub",
  "warning": "",
  "notice": "Жергілікті AI-демо ..."
}
```

Бұл қысқа схема; нақты файлда сұрақтардың толық тізімі бар. `mode`, `warning`, `notice` адаптер валидациясынан кейін қосылады. Ешбір AI шығысы өздігінен расталған немесе жарияланған болып саналмайды.

## Қате өңдеу

| Жағдай | Нәтиже |
|---|---|
| Қысқа сипаттама, белгісіз сала, жарамсыз жауап форматы | HTTP 400, қазақша қате |
| JSON синтаксисі қате / объект емес | адаптер нәтижесі қабылданбайды, қауіпсіз жергілікті талдау |
| Қажетті кілт жоқ немесе артық | сол fallback |
| Мәтін пайдаланушы дерегіне сәйкес емес | ойдан қосылған факт алынып тасталады, fallback |
| Дереккөз тізімі сәйкес емес | fallback |
| Үш сұрақ шарты / детерминдік сұрақтар сәйкес емес | fallback |
| Provider exception, соның ішінде timeout | fallback және `warning` |

Нақты сыртқы HTTP provider жоқ, сондықтан желілік timeout механизмі қосылмаған. Адаптерге келген `TimeoutError` тестпен тексеріледі. Қате жасырынып қалмайды: `warning` клиентке қайтарылады.
